# 2026-09-22 深度产品审查

本轮不是截图级润色,而是沿着“配置 → 接管 → 请求 → 实际去向 → 还原”的闭环审查产品和官网。

## 发现并处理

| 区域 | 问题 | 处理 |
|---|---|---|
| 接管还原 | Codex / OpenCode / OpenClaw 还原会把整个当前文件覆盖为旧备份,可能抹掉用户在接管期间的改动 | 改为只回滚 Keyway 写入的目标字段;发现同一字段被外部修改时中止并保留现场 |
| 多 CLI 路由 | 不同 CLI 共用 `/v1/messages` 或 `/v1/chat/completions`,仅按路径无法判断分组 | 自动接管使用 `/__keyway/{app}` 专属本地前缀,转发前剥离前缀;旧根路径继续兼容 |
| 状态语义 | 旧根路径会被误判为“自动接管有效”,掩盖共享路径带来的串组风险 | 新状态只把应用专属前缀视为有效;旧配置显示为需要重新接管 |
| 存储一致性 | 从已有 CLI 导入时 API Key 仍写入旧 keychain 路径 | 导入改走统一 SQLCipher API-Key 存储入口;旧 keychain 仅保留迁移兼容 |
| 首页闭环 | 只显示默认供应商,用户仍需猜测实际请求去向 | Gateway 卡片增加最近一次实际供应商、模型和 HTTP 状态 |
| 移动端 | Provider 卡片操作组在窄屏会横向裁切,图标按钮缺少可访问名称 | 操作组在移动端换行;图标按钮补 `aria-label` |
| 文案一致性 | 官网仍把 9 个分组写成全部自动接管;指南有“Key 进钥匙串”和 Gemini 绝对重读 `.env` 等过度承诺 | 官网、README、指南和设计文档统一为当前实现边界 |

## 2026-09-23 追加审查

本轮继续沿着“官网演示 → 接管管理 → 状态反馈 → 代理回归”的路径检查,重点补了两个之前容易被忽略的边界:

- 官网 `?demo` 模式的接管管理原先仍会调用桌面端 IPC,点击「接管 / 还原 / 故障转移」会出现假失败;现在改为只在演示模式使用本地状态模拟,桌面端仍走真实命令。
- 接管状态与引导页的 CLI 名称改为走 i18n,健康检测的时间选项也不再混用固定英文单位。
- 尝试收紧“专属路径的协议判定”时,代理集成回归发现 OpenCode 的协议转换链会被破坏;该尝试已撤回,保留“分组由专属前缀决定、请求协议由归一化路径决定”的现有设计,并以回归测试作为约束。

追加验证:

- `npm run build` 通过。

- `cargo test --manifest-path src-tauri/Cargo.toml --test proxy_e2e namespaced_requests_keep_group_protocol_and_usage_independent` 在允许 loopback 的环境中通过。
