# Keyway 产品说明

> AI CLI 的本地网关 —— 让每一次请求,都有清楚、可控的去向。

---

## 一、Keyway 解决什么问题

如果你同时用多个 AI 编程 CLI(Claude Code、Codex、Gemini CLI……),大概率撞过这些墙:

| 痛点 | 具体场景 |
|---|---|
| **配置割裂** | 每个 CLI 一套配置格式(JSON / TOML / .env),换一家供应商要手动改文件、查文档 |
| **切换要重启** | Codex 切完供应商必须重开终端会话,正在跑的活儿被打断 |
| **Key 明文裸奔** | API Key 明文躺在 `settings.json` / `config.toml` 里,误传仓库、被同步工具带上云,都是真实事故 |
| **多供应商管理乱** | 主力 + 备用 + 官方订阅 + 各家国产模型(GLM/Kimi),来回注释改配置 |
| **花费看不清** | 每家供应商各用多少 token,没有统一账本 |

**Keyway 的方向:本地代理优先。** 已接入的 CLI 请求经过本地代理(`127.0.0.1:9527`),由默认供应商、路由规则和故障转移配置决定去向。分组页同时显示默认选择与最近实际去向,请求日志用于确认完整结果。

```
Claude Code ┐
Codex       │──► Keyway 本地代理 ──► 默认选择 / 路由规则 / 故障转移 ──► 上游
Gemini CLI  │    (Key 从加密库读取)     ↑ 默认选择 / 路由规则 / 故障转移
OpenCode    │
OpenClaw    ┘
```

## 二、核心特点

### 1. 默认选择与实际去向分开看 🧭
卡片上的「默认」是未被路由规则覆盖时的供应商选择,并不证明 CLI 已接入代理。先在分组页确认代理与接管状态,再发送请求,通过日志查看实际供应商、模型、状态码和命中的模型规则。

已通过代理的会话切换默认供应商无需重启。首次接管 Codex 后需新开一次会话;切换只影响后续请求,不会迁移已发出的请求。故障转移需配置并启用备用链,不能保证流式响应中断后的无缝恢复。

### 2. 本机加密存储 🔐
- API Key 存入 **SQLCipher 加密数据库**;旧版本的供应商钥匙串记录在读取时迁移
- 数据库主密钥由**系统钥匙串**保管,不是把所有供应商 Key 分别存进钥匙串
- 接管前的原配置自动备份进加密库,一键还原

### 3. 转发即计量 📊
代理从上游响应提取 token 用量并记录请求,无需为计量额外发起模型请求。统计完整性取决于上游返回的 usage;记录缺失不等于没有消耗 token。

### 4. 一键接管,随时还原 🛰️
「接管」把支持的 CLI 配置指向本地代理(改前自动备份);「还原」只回滚 Keyway 自己写入的目标字段。若期间同一字段被 CLI 或其他工具修改,还原会中止并保留现场,避免覆盖用户改动。

### 5. 装上即用的细节 🧰
- **首启导入**:自动发现你现有的第三方配置,一键建好供应商
- **托盘快速切换**:菜单栏右键切换默认供应商;关闭窗口驻留托盘,完全退出则停止代理
- **中英双语**:默认跟随系统,界面与托盘一起切换
- **深浅双主题 / 快捷键**(`⌘N` 新建、`⌘1..5` 切分组)/ **开机自启**
- **轻量**:安装包约 9MB(Tauri 2,非 Electron)

## 三、怎么使用(5 分钟上手)

### 安装并启动
下载安装包(macOS dmg / Windows / Linux,见官网),首次启动时 macOS 弹出钥匙串授权请选「**始终允许**」——那是 Keyway 在保存加密主密钥。

### 三步配置(以 Codex 为例,其他 CLI 同理)
1. **添加供应商**:顶部切到 Codex 分组 → 右上 `+`(或 `⌘N`)→ 填名称、接口地址、API Key → 添加(Key 存入加密数据库)
2. **设为当前**:卡片上点「切换」
3. **接管**:点顶栏绿色「代理运行中」→ 对应 CLI 行点「接管」

首次接管 Codex 后新开一次会话。发送新请求,在分组页点击「查看请求去向」,确认日志里的供应商与响应状态。接管状态反映配置,不是对每个正在运行的会话的实时探测。

> 没有现成供应商?看看 [GLM 接入](./providers/glm.md)、[Kimi 接入](./providers/kimi.md)、[CoderPlan 接入](./providers/coderplan.md) 和 [RELAY 接入](./providers/relay.md)。

### 日常操作速查

| 想做什么 | 怎么做 |
|---|---|
| 切换供应商 | 卡片「切换」/ 托盘右键;发送新请求后查看日志 |
| 添加 / 编辑 / 删除供应商 | `⌘N` / 卡片铅笔 / 卡片垃圾桶 |
| 复制接口地址 | 点卡片上的地址 |
| 回官方登录 | 接管面板「还原」 |
| 看用量 | 卡片右侧自动累计 |
| 换语言 / 主题 / 开机自启 | 设置(齿轮) |
| 让 CLI 恢复直连 | 接管面板对应行「还原」 |

## 四、数据与安全

| 数据 | 位置 | 保护 |
|---|---|---|
| API Key | 本机 `conduit.db` | SQLCipher 整库加密 |
| 数据库主密钥 | 系统钥匙串 | 系统凭证存储 |
| 供应商配置 / 接管备份 / 用量 | 应用数据目录 `conduit.db` | SQLCipher 整库加密 |
| 各 CLI 原配置 | 接管前备份进加密库 | 还原时解密写回 |

配置与用量记录保存在本机。代理会将请求内容与认证信息发送给所选模型供应商;本地存储不代表离线推理。导出的供应商配置不含 API Key。接管前已存在的 CLI 配置文件需由用户自行检查,加密数据库不会追溯清除其他文件里的明文凭证。

## 五、产品定位与选择

Keyway 聚焦本地请求的运行与排查:现在配置了谁、CLI 是否接入代理、实际请求到了哪里、失败后怎样检查或还原。代理、日志和故障转移本身不作为独家能力宣传。

选择工具时,建议用自己的 CLI 工作流验证首次接入、切换、上游失败和恢复直连。这里不保留未经持续核验的竞品功能差异表,也不对竞品存储安全性作推断。

## 六、常见问题

**Q:接管会破坏我的现有配置吗?**
接管前原配置会备份进加密库。还原时 Keyway 只回滚自己写入的目标字段;如果 CLI 或其他工具在接管期间修改了同一字段,操作会中止并保留现场,避免覆盖用户改动。Claude 的 `settings.json` 只动 `ANTHROPIC_BASE_URL` 一项,Codex 的 `config.toml` 会保留无关改动与注释。

**Q:Keyway 没开,我的 CLI 还能用吗?**
接管模式下 CLI 会指向本地代理,Keyway 未运行则请求失败——建议开启「开机自启」(设置里),或让 Keyway 驻留托盘。介意的话随时「还原」回直连。

**Q:支持哪些供应商?**
任何 Anthropic / OpenAI / Gemini 兼容的供应商:官方、GLM、Kimi、DeepSeek、各类中转站,或自建网关。

**Q:能和其他 CLI 管理器同时用吗?**
可以安装在同一台电脑上,但同一个 CLI 不要同时让两个工具接管。Keyway 会只读检查外部管理器的接管状态;检测到其他工具正在管理时,Keyway 会暂停写入,不会强行覆盖。要改用 Keyway:先在其他工具中关闭代理并回到直连,再在 Keyway 里接管。反向切换时也先还原当前工具的配置。

**Q:我想把其他管理器里的供应商带到 Keyway,会覆盖原配置吗?**
不会。Keyway 的外部配置导入只读取供应商记录,不会写入原管理器数据库、供应商文件或 CLI live 配置。扫描时会排除本地代理地址和环境变量占位符;同名同地址会跳过,同名不同地址会自动生成不冲突的名称,不会覆盖已有 Key。导入供应商与接管 CLI 是两个独立动作。

**Q:如果要在两个 CLI 管理器之间切换,具体怎么做?**
同一时间只能有一个工具拥有 `~/.codex/config.toml` 的 live 配置。先在当前工具中关闭代理并恢复直连,再在另一个工具中执行接管;不要只因为两个本地端口不同就同时开启。切换后新开一次 CLI 会话,发送请求并在 Keyway 日志中确认实际供应商。

**Q:为什么 Keyway 的「接管」按钮被禁用了?**
检测到该 CLI 的配置由其他管理器管理。请先在对方关闭代理/回到直连,再刷新 Keyway;在此之前 Keyway 不会备份或改写该配置,以免两个代理互相覆盖。
