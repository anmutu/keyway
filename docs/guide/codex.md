# Codex 使用指南

> 在 Keyway 中配置并管理 OpenAI Codex CLI 的供应商:添加 Key、接入本地代理、查看实际请求去向并安全恢复。

## 它是怎么工作的

```
codex CLI ──► Keyway 本地代理(127.0.0.1:9527)──► 默认选择 / 路由 / 故障转移 ──► 上游
```

- **接管**会把 `~/.codex/config.toml` 中的供应商 `base_url` 改写为 `http://127.0.0.1:9527/__keyway/codex`(改写前自动备份)。新建的 Keyway 条目使用 Responses 协议。
- 你的 **API Key 存在本机 SQLCipher 加密数据库**,数据库主密钥由系统钥匙串保管;代理转发时向上游注入认证信息
- **切换默认供应商只改本地选择**——已通过代理的会话通常无需重启;切换影响后续请求,路由规则可能覆盖默认选择

## 前置条件

| 需要 | 说明 |
|---|---|
| Codex CLI | 已安装并可运行 `codex` 命令 |
| 一个 OpenAI 兼容供应商 | 供应商提供的 `base_url` + `API Key` |
| Keyway | 已启动,顶栏显示绿色「代理运行中」 |

## 配置四步

### ① 切换到 Codex 分组

窗口顶部应用切换胶囊中点击 **Codex**。

### ② 添加供应商

点击右上角 **+** 按钮(或按 `⌘N` / `Ctrl+N`):

| 字段 | 填写说明 | 示例 |
|---|---|---|
| 名称 | 自定义,方便辨认 | `CoderPlan` |
| 接口地址 | 供应商给的地址。**带不带 `/v1` 都可以**,Keyway 会自动处理 | `https://api.example.com/v1` |
| API Key | 供应商提供的 Key,存入本机加密数据库 | `sk-...` |

点击「添加」。

> macOS 启动时可能请求访问数据库主密钥;请核对应用来源后决定是否授权。添加供应商的 API Key 写入本机加密数据库。

### ③ 设为当前供应商

在供应商卡片上点击「**切换**」。卡片出现「默认」徽章表示默认选择已更新,不代表正在运行的 CLI 已使用它。

### ④ 接管 Codex

1. 点击顶栏绿色的「**代理运行中**」标签,打开「代理接管」面板
2. 在 **Codex** 一行点击「**接管**」
3. 状态反映选中的供应商配置是否指向代理;请继续发送新请求确认实际接入

接管后请**新开一次** codex 会话并发送请求,在请求日志确认已经过 Keyway。之后切换默认供应商通常无需重启,但路由规则可能覆盖默认选择。

## 从 CC Switch 迁移或交接

Keyway 与 CC Switch 可以同时安装,但 Codex 的 live 配置不是两边各一份:

```text
供应商记录可以共存
~/.codex/config.toml / ~/.codex/auth.json 同一时间只能由一个工具接管
```

在 Codex 分组页点击「从 CC Switch 导入」即可选择性复制供应商。Keyway 只读 `~/.cc-switch/cc-switch.db`(也兼容系统配置目录),不修改 CC Switch;本地代理地址、`PROXY_MANAGED` 和环境变量引用会被过滤。导入不会自动接管 Codex,也不会删除 CC Switch 中的记录。

### 从 CC Switch 切到 Keyway

1. 先导入需要的供应商,确认 Keyway 卡片中的地址和 Key 状态。
2. 在 CC Switch 中关闭 Codex 代理并恢复直连,让它释放 `config.toml` 与数据库中的接管状态。
3. 回到 Keyway,打开「管理接管」并点击 Codex「接管」。检测到 CC Switch 仍持有配置时,Keyway 会拒绝写入并提示原因。
4. 新开 Codex 会话,发送请求,在「请求日志」确认实际去向。

### 切回 CC Switch

先在 Keyway 的 Codex 行点击「还原」,再在 CC Switch 中重新启用代理。不要通过同时启动两个不同端口的本地代理来规避交接:端口不同不代表 Codex 会同时使用两份配置,后写入的一方可能覆盖前一方,请求也会绕过另一方的日志和路由。

### 导入限制

官方 OAuth 登录、只引用环境变量的 Key、CC Switch 自己的本地代理记录无法安全复制为 Keyway 的 API Key,会在导入窗口标记为不可迁移。此时可在 Keyway 中手动添加供应商并粘贴 Key;原始 CC Switch 配置保持不变。

## 日常使用

### 切换默认供应商并确认

- **主界面**:卡片 hover → 「切换」
- **托盘**:菜单栏 Keyway 图标 → 右键 → Codex → 选择供应商(当前项有 `●` 标注)

已经接入代理的会话切换默认供应商无需重启。路由和故障转移可能改变实际去向,请查看最近请求记录。

### 查看用量

每次请求经代理转发时自动统计,无需任何配置。卡片右侧显示:

```
128 次请求
↓ 412.0k · ↑ 1.3M
```

### 修改供应商

卡片 hover → 铅笔图标。名称、地址可直接改;API Key 留空表示保持不变,填新值则更新到本机加密数据库。

### 复制 / 删除

- 复制:卡片 hover → 复制图标(快速建一个改改地址的副本)
- 删除:卡片 hover → 垃圾桶图标(需二次确认,保存的 API Key 一并清除)

## 取消接管(还原官方配置)

1. 点击顶栏「代理运行中」标签
2. Codex 行点击「**还原**」

还原会撤销 Keyway 改写的供应商地址并保留无关设置;如果目标字段或自动创建的条目被外部修改,操作会中止,文件与备份保留。恢复后新开会话并确认直连。

## 故障排查

| 现象 | 原因与处理 |
|---|---|
| 接管面板显示「未检测到配置」 | 你还没运行过 Codex。可先跑一次 `codex` 生成配置,或直接点「接管」——Keyway 会创建最小配置 |
| 状态显示 ⚠️「配置被外部修改」 | Codex 或其他工具改写了 `config.toml`。重新点一次「接管」即可 |
| codex 报 `Connection refused` / 请求失败 | ① 确认 Keyway 正在运行(托盘有图标);② 确认顶栏是绿色「代理运行中」;③ 若红色,重启 Keyway |
| codex 报 502「未设置 codex 的当前供应商」 | 当前分组里没有任何供应商被设为「当前」——去主界面给某张卡片点「切换」 |
| codex 报 401 / 鉴权失败 | 供应商的 API Key 不对:编辑供应商,重新填 Key(检查是否复制完整、有无多余空格) |
| 模型不存在 / 404 model not found | 供应商不 support 你 `config.toml` 里 `model = "..."` 配置的模型名,改用该供应商支持的模型 |
| 地址填了带 `/v1`,担心拼错 | 不用担心:Keyway 自动去重 `/v1/v1`,带不带 `/v1` 均可 |
| 钥匙串反复弹窗 | 打开「钥匙串访问」→ 搜索 `conduit` → 该条目访问控制中勾选「始终允许」 |

## 数据与安全

| 数据 | 位置 | 保护 |
|---|---|---|
| API Key | 本机 `conduit.db` | SQLCipher 整库加密 |
| 数据库主密钥 | 系统钥匙串 | 系统凭证存储 |
| 供应商配置 / 接管备份 / 用量记录 | `~/Library/Application Support/com.conduit.desktop/conduit.db` | SQLCipher 整库加密(主密钥在钥匙串) |
| 接管时的原配置备份 | 同上(加密 DB 内) | 还原时解密写回 |

## 快捷键速查

| 快捷键 | 功能 |
|---|---|
| `⌘N` / `Ctrl+N` | 添加供应商 |
| `⌘1` ~ `⌘5` | 切换应用分组(Claude / Codex / Gemini / OpenCode / OpenClaw) |
| `Esc` | 关闭弹窗 / 从设置页返回 |
