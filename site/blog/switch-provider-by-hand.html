换一家 AI 供应商,你的电脑上要动哪三个地方?

博客 · 系列 · 第 1 篇 · 2026-11-06 · 约 6 分钟 · 作者

30 秒答案:要动三个地方——①接口地址(Base URL),写进 CLI 的配置文件;②API Key,通常存成环境变量;③让 CLI 用上它,把默认供应商指过去并新开一个会话。三个 OS 的区别只是"文件在哪个目录、环境变量怎么存"。

一、先看清链路:一次请求的完整旅程

无论 Codex、Claude Code 还是 Gemini CLI,手动配置前先知道你改的东西在链路里的位置:

你敲下回车
   │
   ▼
AI CLI 进程(启动的那一刻就已经读完了配置)
   │   ① 接口地址 Base URL ──── 请求发往哪台服务器
   │   ② API Key          ──── 用什么身份去发
   │   ③ 模型名 / 参数
   ▼
HTTPS 请求(地址 = Base URL + 路径;认证 = 请求头里的 Key)
   │
   ▼
上游服务器(官方 或 第三方供应商)
   │
   ▼
流式返回 ──► CLI 在终端里逐字渲染

所有"换供应商"的动作,本质上都是改这张图最上面的两样东西——接口地址(Base URL)和 API Key。此外通常还有第三样要跟着动:模型名,因为同一个模型在不同供应商那里的命名常常不同,照抄旧名字很可能报"模型不存在"。至于 CLI 的其他能力——对话、工具调用、上下文管理——和供应商配置完全无关,一行都不用碰。

二、三个必须搞懂的概念

① 接口地址(Base URL)—— 门牌号

官方 CLI 出厂自带官方地址;换成第三方供应商,就是把这个地址改成供应商给你的那串 URL,例如 https://api.example.com/v1。注意 /v1:有的供应商地址里已带、有的要求你自己补,以它的博客为准——路径不对的典型报错是 404。

② API Key —— 身份证

从供应商控制台生成,形如 sk-xxxx…。CLI 发请求时把它放进 Authorization 请求头。它绑定供应商:A 家的 Key 在 B 家就是一张废卡。放哪最常见:环境变量(下面三 OS 详解)。

③ 协议 —— 三家方言

Anthropic、OpenAI、Gemini 是三种不同的接口协议。Claude Code 只认 Anthropic 兼容端点,Codex 只认 OpenAI 兼容端点,Gemini CLI 只认 Gemini 格式,互不通用。你经常看到第三方供应商标注"OpenAI 兼容",意思是它可以接一切说这种方言的 CLI。买 Key 之前先确认协议对得上(供应商通常会注明它兼容哪种或哪几种协议)。

三、macOS / Windows / Linux:分别去哪改

CLI 的配置文件都藏在你的用户主目录下:

主目录在哪Codex 配置(示例)
macOS/Users/你/(终端里 ~ 就是它)~/.codex/config.toml
WindowsC:\Users\你\(资源管理器地址栏输入 %USERPROFILE%)%USERPROFILE%\.codex\config.toml
Linux/home/你/(同样用 ~)~/.codex/config.toml

环境变量:三家 OS 的持久化方式不同

写入方式(永久生效)让当前窗口立刻生效
macOS在 ~/.zshrc 末尾加 export MY_KEY="sk-xxx"source ~/.zshrc,或新开终端窗口
WindowsPowerShell 运行 setx MY_KEY "sk-xxx"(写入用户变量)必须新开 PowerShell 窗口,setx 不影响当前窗口
Linux在 ~/.bashrc(或 ~/.zshrc)末尾加 export MY_KEY="sk-xxx"source ~/.bashrc,或新开终端

共同的大坑:CLI 进程只在启动那一刻读一次环境变量和配置文件。你改完文件,正在运行的 CLI 不会知道——新开终端窗口 → 新开 CLI 会话,是每次手动配置的标准收尾动作。

四、怎么确认配成功了?通用三板斧

  1. 环境变量在不在:echo $MY_KEY(macOS/Linux)或 echo $env:MY_KEY(Windows PowerShell)。打印出 Key 内容才算在。
  2. 地址通、Key 对:直接向上游发一条最小请求(以 OpenAI 兼容接口为例): 
    curl https://api.example.com/v1/models \
  -H "Authorization: Bearer $MY_KEY"
    返回 JSON 模型列表 = 地址和 Key 都对;401 = Key 错;404 = 地址路径错(多半是 /v1 的问题);超时 = 网络不通。
  3. CLI 实测:新开会话随便问一句,能正常回复,链路即通。

五、手动方案的天花板

单次配置其实不难,难的是反复:换一家 = 上面全套再来一遍;两家来回切 = 配置文件改来改去,每次都要记得新开会话;手一抖改错一个字符,报错还未必直白。这是所有"改文件"方案的共同宿命——文件没有记忆,也不认识"切换"这个词。

本系列先把每家的手动配置彻底讲透,再谈怎么把这些麻烦一次性解决。下一篇,从 Codex 开始动手。

常见问题

改了配置为什么没生效?

CLI 进程启动时读一次配置和环境变量,之后不再重读。新开终端窗口、新开 CLI 会话即可。

API Key 放在本机安全吗?

本机的环境变量/配置文件只有能登录你电脑的人能读。真正的风险是截图、上传、把带 Key 的文件提交进 git 仓库。

/v1 到底带不带?

以供应商博客为准。经验规律:官方 OpenAI 地址带 /v1,很多第三方供应商两种写法都兼容;404 时优先怀疑它。

三家的 Key 能混用吗?

跨供应商:绝对不能。Key 绑定的是签发它的那家服务——OpenAI 的 Key 在 Anthropic 端点就是无效字符串(401),反之亦然。但同一把第三方 Key,可以在其供应商的多个协议端点上通用(前提是它同时提供 Anthropic / OpenAI 兼容接口)——协议是端点的属性,不是 Key 的属性。
