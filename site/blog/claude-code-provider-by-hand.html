Claude Code 手动换供应商:settings.json 与环境变量,谁说了算?

博客 · 系列 · 第 3 篇 · 2026-11-06 · 约 7 分钟 · 作者

30 秒答案:Claude Code 换供应商 = 改 ~/.claude/settings.json 里的 env 块:设 ANTHROPIC_BASE_URL(发往哪)+ ANTHROPIC_AUTH_TOKEN 或 ANTHROPIC_API_KEY(用什么身份),保存后新开会话。它比 Codex 多一个坑:配置可以写在两个地方(配置文件和终端环境变量),只留一处是铁律。

一、Claude Code 的配置版图

Claude Code 涉及的位置同样只有三个角色:

位置管什么本文动不动
~/.claude/settings.json用户级设置,其中 env 块可以写入环境变量——手动换供应商的推荐位置。✅ 主战场
终端环境变量在 .zshrc / .bashrc / setx 里导出同名变量,效果等价。⚠️ 与上面二选一
~/.claude.json(登录态等)Claude Code 自己维护的运行状态,含官方订阅登录信息。❌ 不要手改

为什么推荐 settings.json:它是一个普通 JSON 文件——可备份、可 diff、换机器能整体迁移;而散落在 shell 配置里的变量看不见摸不着,三个月后你自己都想不起来设过什么。

二、动手:四步完成

第 1 步 · 备份并打开 settings.json

macOSLinux

cp ~/.claude/settings.json ~/.claude/settings.json.bak
nano ~/.claude/settings.json   # macOS 也可 open -e

Windows(PowerShell)

copy $env:USERPROFILE\.claude\settings.json $env:USERPROFILE\.claude\settings.json.bak
notepad $env:USERPROFILE\.claude\settings.json

第 2 步 · 写入 env 块(可直接抄,改两处)

{
  "env": {
    "ANTHROPIC_BASE_URL": "https://api.example.com",
    "ANTHROPIC_AUTH_TOKEN": "sk-你的key"
  }
}
  • ANTHROPIC_BASE_URL:供应商给的 Anthropic 兼容地址。
  • ANTHROPIC_AUTH_TOKEN:以 Bearer 方式发送,第三方端点最常用。ANTHROPIC_API_KEY 则走 x-api-key 头(官方 API 方式)——用哪个看供应商博客,通常只设一个。
  • 文件里已有其他配置(如 permissions)?保留它们,只增改 env 块。

第 3 步 · 清掉另一处的旧变量(防打架)

如果你以前在终端里导出过这些变量,现在两处同时存在,行为取决于各处的加载时机,排查起来非常痛苦。检查并清理:

# macOS / Linux:看看 shell 配置里有没有残留
grep -n "ANTHROPIC" ~/.zshrc ~/.bashrc 2>/dev/null

# Windows PowerShell:看用户变量里有没有
Get-ChildItem env: | Where-Object Name -like "ANTHROPIC*"

有残留就删掉对应行(或 Remove-Item Env:ANTHROPIC_xxx 仅清当前窗口),保证唯一来源是 settings.json。

第 4 步 · 新开会话并验证

  1. 新开终端窗口 → 新开 Claude Code 会话;
  2. 随便问一句,正常回复即通;
  3. 排查时可用 curl 直测上游: 
    curl https://api.example.com/v1/messages \
  -H "x-api-key: sk-你的key" \
  -H "anthropic-version: 2023-06-01" \
  -H "content-type: application/json" \
  -d '{"model":"claude-3-5-haiku-latest","max_tokens":16,"messages":[{"role":"user","content":"hi"}]}'
    返回正常 JSON = 地址与 Key 双双正确;401 = Key 或认证方式选错(试试换另一个变量);404 = 地址路径不对。

三、常见坑速查

症状最可能的原因解法
改完没变化旧会话未重启 / 两处定义打架新开会话;确认只有 settings.json 一处定义
401AUTH_TOKEN 与 API_KEY 用错边按供应商博客换另一个变量
404base_url 路径不对对照供应商博客;Anthropic 端点一般不额外带 /v1 之外的路径
JSON 解析报错settings.json 少了逗号/引号JSON 校验器过一遍再保存

四、切换成本:和 Codex 一样的宿命

换回官方、换第二家、来回切——每一步都是"改文件 → 新开会话"的循环,而且 Claude Code 的订阅登录与 API 模式还会互相穿插(订阅登录时不需要任何 env,一旦设了 BASE_URL 则走自定义端点)。手动管理三家 CLI 的配置,文件越改越像一张藏宝图。下一篇看 Gemini CLI,它的坑最特别:配置在一个 .env 文件里,而且只在进程启动时读。

常见问题

订阅(Claude Pro/Max)和这些配置冲突吗?

订阅登录时 Claude Code 走官方 OAuth,不需要这些变量;一旦设置了 ANTHROPIC_BASE_URL,请求就改发你指定的端点。两种是不同模式,别同时混用。

项目级和用户级 settings 有什么关系?

项目目录下还可以有 .claude/settings.json,会与用户级合并。给某个项目单独配供应商是可行的,但手动管理两层的合并结果会更绕,新手建议先只动用户级。

Key 写进 settings.json 安全吗?

与放在 shell 配置里安全等级相同(本机可读)。底线同样是:不要把带 Key 的文件提交进 git、不要截图外发。备份文件(.bak)同样含 Key,注意同样对待。
