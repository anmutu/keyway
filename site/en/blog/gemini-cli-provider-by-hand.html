Gemini CLI, by hand: .env, the base URL and two auth modes

Blog · Series · Part 4 · 2026-11-06 · ~5 min · author

The 30-second answer:Gemini CLI's provider config lives in ~/.gemini/.env: two lines — GOOGLE_GEMINI_BASE_URL and GEMINI_API_KEY. If you previously logged in with a Google account, switch auth to API key via /auth first. Then restart the gemini process — .env is read exactly once at startup, which is its most famous trap.

1. Gemini CLI's config map

2. Hands on: four steps

Step 1 · Edit (or create) .env

macOSLinux

# create if missing; back up if present: cp ~/.gemini/.env ~/.gemini/.env.bak
cat >> ~/.gemini/.env <<'EOF'
GOOGLE_GEMINI_BASE_URL=https://api.example.com
GEMINI_API_KEY=sk-your-key
EOF

Windows(PowerShell)

Add-Content $env:USERPROFILE\.gemini\.env "`nGOOGLE_GEMINI_BASE_URL=https://api.example.com"
Add-Content $env:USERPROFILE\.gemini\.env "GEMINI_API_KEY=sk-your-key"

Format rules: one NAME=value per line, no spaces around =, no quotes around values (dotenv style). If the provider's URL includes a path, keep it exactly as documented.

Step 2 · Make sure auth mode is API key

If you ever logged in with a Google account, auth is still OAuth — and it ignores your key. Start gemini, type /auth, and pick API key mode. The choice is stored in settings.json; once is enough.

Step 3 · Restart the process (the soul of this article)

Gemini CLI reads .env exactly once, at process startup. A running session never notices your edits: exit gemini and start it again. If "nothing happened", 99% it's this.

Step 4 · Verify

  1. Ask anything in the new process — a normal reply means it works;
  2. To check the variables were picked up: 
    grep . ~/.gemini/.env          # file contents correct?
curl "$GOOGLE_GEMINI_BASE_URL" -I   # address reachable? (any HTTP status = reachable)
  3. Errors: 401/403 = key or auth mode (revisit step 2); 404 = wrong path; model not found = use a name from the provider's list.

FAQ

Does .env need export?

No. dotenv is plain NAME=value; adding export or quotes may be read as part of the value.

Must third-party endpoints speak the Gemini format?

Yes. Gemini CLI only speaks Gemini-format APIs; Anthropic/OpenAI-compatible endpoints can't be attached. Look for providers that explicitly support Gemini CLI / the Gemini format.

Does the base URL need a version path?

Follow the provider's docs; Gemini-format endpoints usually point at the API root and the CLI appends the path. Compare with the docs when you see 404.
