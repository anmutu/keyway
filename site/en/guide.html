1
Get ready

Download & install

Keyway is a desktop local gateway, not an online chat tool, and does not install AI CLIs for you. Choose a chip-matched DMG on macOS, an installer on Windows, or an architecture-matched AppImage, deb or rpm on Linux.

  • Prepare your CLI: Install your AI CLI separately and confirm it starts in a terminal. Keyway manages where its requests go.
  • Prepare a provider: Obtain an API key, API Base URL and supported model names. Do not assume a web chat subscription includes API credits; check provider account permissions.
  • Protect existing settings: Save a separate copy of CLI configuration before first takeover. Avoid multiple switching tools rewriting the same file. Start with one CLI.

Download for Apple silicon (M1–M4) Intel version Windows Linux AppImage Linux .deb Linux .rpm All platforms ›

  • On macOS, if the developer cannot be verified, right-click Keyway in Applications and choose Open; on Windows, choose “More info” → “Run anyway” if SmartScreen appears.
  • On macOS, check the version and file name shown by the download button (for example, Keyway_{version}_aarch64.dmg). If it says “no application can open it”, delete the incomplete download and download again.
  • On Linux, make the AppImage executable before opening it (for example, chmod +x Keyway_{version}_amd64.AppImage).
  • Keyway lives in the menu bar or system tray; closing the window keeps the local proxy running on 127.0.0.1:9527.
How does it work? Connected requests follow default providers, routing rules and failover settings. The default is not proof of the actual destination: check request logs. Sessions already using the proxy need no restart when changing defaults.

Set up

Add providers

Open the main window and add model providers per CLI group (Claude Code, Codex, Gemini CLI and more):

  • Presets: common providers and relays built in — just paste an API key.
  • Import from existing configs: already configured a CLI? Import in one click, no retyping.
  • Custom: name, Base URL and API Key — any relay or self-hosted gateway works.
  • Example — Teapot Router: preset pinned at top with the endpoint prefilled; click “Get API Key” to open teapotrouter.com/en/dashboard/keys, create and copy a key, then paste it back.

Coming from another switcher: scan → select → imported. Source configs are read-only

Key storage: API keys live in a local SQLCipher-encrypted database; its master key is held in the system keychain. Provider configuration exports exclude API keys. Authentication is still sent to the selected upstream when forwarding requests.

After adding, hit the test button on a provider card to check reachability and latency before committing.

What goes in each field?

  • Name: Use a recognizable name such as Primary or Backup. Before editing, check whether other CLI groups share the provider.
  • Endpoint: Use the API Base URL from provider documentation, not a website, dashboard or complete /chat/completions URL. Choose the actual protocol. https://api.example.com/v1 is a placeholder, not a working service.
  • API key: Paste the provider key and keep it out of tickets and screenshots. Leaving it blank when editing preserves the existing key. Re-enter keys after migrating configuration.
  • Model: Use an exact model name supported upstream. The card’s model list is informational: it does not rename CLI models or grant access. Configure the requested model in your CLI.
A reachability test is not full validation. Select the provider as current/default, take over the CLI and send a real request. Initially avoid complex routing and failover to make failures easier to isolate.

Takeover

One-click CLI takeover

Click the gateway status in navigation or “Gateway details” on a group page, then choose the target CLI in takeover management. After takeover, Keyway points that CLI's config at the local proxy:

  • Original configs are backed up before takeover and can be restored in takeover management. Review any manual changes you want to keep first.
  • Start a new Codex session after first-time takeover. Keep Keyway running while using the proxy; restore configs before fully quitting if you need direct connections.
  • Prefer manual? Set the CLI's environment variables to 127.0.0.1:9527 instead (copyable from the app).

Switch and verify requests

The default provider is a selection, not proof of the actual destination. After switching, send a new request and verify its provider in the logs:

Looking for advanced tools?Usage, MCP, Skills, Settings, and the guide are under “More” in navigation. Selecting a page closes the menu; Escape dismisses an open menu without leaving the current page.
  • Click “Switch” on a provider card, or pick from the menu-bar tray. The selection applies to subsequent requests.
  • Global shortcut ⌘⇧K (Ctrl+Shift+K on Windows/Linux) opens the quick-switch panel anywhere: ↑↓ to select, Enter to switch, Esc to dismiss — hands stay on the keyboard.
  • Sessions already using the proxy need no restart. Switching affects new requests, not in-flight ones; routing rules may override the default provider.
  • One provider can serve multiple CLIs per protocol (e.g. one relay key for both Claude Code and Codex).
  • Responses bridge: per-provider toggle converts Codex /v1/responses requests to /v1/chat/completions for chat-only relays; enable it when editing a provider. Native Responses providers like official OpenAI do not need it.
  • Protocol conversion has limits: Keyway implements selected Anthropic, OpenAI Chat and Gemini conversions. This does not guarantee lossless support for every model, tool, multimodal or reasoning parameter. Prefer native endpoints. Enable Codex Responses bridging separately and verify it with real tasks.
  • Balance lookup: for OpenRouter-compatible relays, click the wallet icon on a provider card to view used and total quota before you need to top up.
  • Unified MCP management: define MCP servers once in Keyway and they are written into Claude Code's and Codex's configs automatically; manually configured entries are untouched.
  • The local proxy exposes http://127.0.0.1:9527/healthz returning the version and each CLI group's current provider — handy for scripts and health checks.
  • More in-app shortcuts: ⌘N new provider, ⌘1..5 switch CLI group, ⌘⇧M / ⌘⇧S jump to MCP / Skills management (Ctrl combos on Windows/Linux).
  • Unified Skills management: maintain skills in a local vault and sync them to Claude Code and Codex in one click; built-in or manually added skills are untouched.

Practical verification

Did my first request actually go through Keyway?

  1. Start with one group: Select your CLI, add a provider and click Switch. Confirm it is selected, not merely listed.
  2. Check the proxy: Keep Keyway running. Run curl http://127.0.0.1:9527/healthz (use curl.exe in PowerShell). The returned status, version and defaults prove local reachability, not upstream connectivity.
  3. Take over and start a fresh session: Connect the target CLI. Codex needs a new session after first takeover. Restart other CLI sessions if they retain old settings. Terminal or project settings may affect Gemini environment variables.
  4. Send a simple message: Ask the CLI “Reply only OK; do not read or write files or call tools.” This is a real request and may incur charges. Avoid long tasks and sensitive content for the first test.
  5. Inspect logs: Open Logs for the same group and refresh. Check the new entry’s time, provider, model and HTTP status. A CLI reply plus its matching log completes basic verification.
  6. Test switching: Add a backup, switch and send another message. Check its new log. Routing or failover may override the default; an earlier log cannot prove a new switch worked.
Three different states: A running proxy means the listener exists; takeover means configuration points to it; a new log proves a request passed through it. The newer home screen’s last destination is historical, not a live session guarantee.
5
Advanced

Routing · failover · logs · profiles

Model routing rules — in Settings → Model routing, keep specific models on specific providers:

  • E.g. rule claude → relay A; rule deepseek → official. Name the model in your CLI and Keyway dispatches it.
  • Match by “contains” or “starts with” — the prefix mode is more precise and avoids accidental keyword hits.
  • Each rule can be temporarily disabled with a toggle, keeping its config. Rules match top to bottom (first match wins); reorder with ↑↓.
  • Requests that matched a rule are tagged blue in the Logs page, so routing is visible at a glance.
  • Scene-based split: besides long-context, designate providers for deep-think (thinking enabled or reasoning/thinking tier models) and background-lite (haiku / mini / flash / nano tier tasks) — premium models where they matter, cheap channels for small jobs.
  • Long-context split: requests above a size threshold (adjustable, ~60k tokens estimated by default) automatically go to a designated provider — big contexts on the cheap channel, daily chats unaffected. Matched responses carry an x-keyway-route header.

Automatic failover — verify primary and backup providers, including support for the requested model. Enable failover for the group and inspect its candidate chain. Retryable connection failures, 429 and 5xx can try later candidates; not all errors retry and mid-stream recovery is not guaranteed. Check the x-keyway-fallback response header when fallback occurs.

Usage & logs — the Usage page aggregates tokens and success rates by CLI and provider; Logs shows the last 100 requests (model, tokens in/out, status) for easy debugging; logs are grouped by day, and an optional periodic health check in Settings tests the current providers on a schedule and syncs to the tray.

Profiles & backup — save the current provider set as a profile (work / personal / testing, one-tap switching) and export a JSON backup via the system save dialog (keys excluded) for moving machines. Config export / import shares providers, route rules and presets as a portable JSON — imports merge by name, so teams can share setups in one step.

6
Safe exit and migration

How do I stop using the proxy safely?

  1. Finish ongoing requests. Closing the window can leave Keyway in the tray. Fully quitting stops the proxy; CLIs still pointing to it cannot continue through it.
  2. Restore each connected CLI in takeover management. On older versions, first save a copy of current configuration to protect newer edits. Newer conflict protection stops restoration and preserves files when managed fields changed. Do not delete backups or force overwrites.
  3. Review manual settings. Variables added to terminals, shell startup files or projects may not be removed by automatic restore. Restore their original values from your change record. Verify direct access in a new CLI session before quitting or uninstalling.

Moving machines: Export a provider backup or shareable configuration → save the JSON securely → install and import on the new device → re-enter API keys → verify providers → take over CLIs again. Profiles save default provider selections, not full backups. Configuration exports exclude keys and do not replace backups of CLI files or request logs.

Troubleshooting

Having trouble?

  • The CLI replies but no new log appears: Refresh and confirm the group. Check terminal variables, project settings and other switching tools for overrides. A selected provider card alone is not proof.
  • Connection refused: Confirm Keyway has not fully quit and check /healthz. If the port is occupied, establish whether another instance owns it; do not terminate unknown processes blindly.
  • 404 / model not found: Check the Base URL, protocol and requested model. Codex Responses requests require upstream support; Chat-only channels need separate bridge compatibility testing.
  • 429 / 5xx: Check rate limits, quota and upstream availability. Reduce request frequency or switch to a verified backup. Avoid rapid retries that worsen rate limiting.
  • 401 / 403 responses carry an x-keyway-hint header — follow it to check key validity and quota.
  • Switch not taking effect: check proxy and takeover status, send a new request, then inspect its log. Model routing can override the default provider; first-time Codex takeover needs a new session.
  • Want your original setup back? Click “Restore” on the group page — the original config was backed up at takeover.
  • Where's my data? Configuration and usage records are encrypted locally. Request content and authentication go to the selected upstream. Uninstalling does not guarantee removal of app data or keychain entries.
