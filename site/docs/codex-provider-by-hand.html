Codex 手动换供应商:config.toml 逐行讲解

文档 · 系列 · 第 2 篇 · 2026-11-06 · 约 8 分钟 · 作者

30 秒答案:Codex 的供应商配置全部在 ~/.codex/config.toml:写一个 [model_providers.名字] 块填接口地址,Key 放进块里 env_key 指定的环境变量,顶层 model_provider 指向这个块,然后新开终端 + 新开 codex 会话。改文件不重启会话,等于什么都没改。

一、Codex 的链路:启动那一刻就定了

codex 会话启动
   │
   │ 读取 ~/.codex/config.toml(只读这一次!)
   │    model_provider = "myrelay"        ← 当前用哪家
   │    [model_providers.myrelay]
   │       base_url = "https://…"          ← 请求发往哪
   │       env_key  = "MYRELAY_API_KEY"    ← Key 的变量名
   │
   │ 从环境变量里取出 MYRELAY_API_KEY
   ▼
HTTPS 请求 ──► base_url 指向的供应商 ──► 流式返回

看懂这张图,后面所有操作都不再是"照抄命令",而是"我知道我在改链路的哪一环"。

二、先认门:Codex 的配置都在哪、各自管什么

动手之前,先把 Codex 在你电脑上的配置版图看一眼。它涉及的文件其实只有三个角色,今天我们只动其中一个:

文件 / 位置管什么本文动不动
~/.codex/config.toml主配置:供应商列表、默认用哪家、模型、审批策略等。手动换供应商的主战场。✅ 全文就改它
~/.codex/auth.jsonOpenAI 官方登录凭据(订阅模式登录后自动生成)。用自定义供应商时用不到它。❌ 不要动
环境变量(名字由你定)API Key 的存放处,config.toml 通过 env_key 字段按名字引用它。✅ 第 3 步

另外两点先打个预防针:

  • config.toml 里通常不止供应商配置——模型选择、安全策略等也在这里。本文只增改供应商相关的行,其他行原样保留;改前备份(第 1 步会做)。
  • 如果文件不存在,说明你还没做过任何自定义——第 1 步会新建一个,Codex 会照常读取。

Windows 用户把 ~ 换成 %USERPROFILE%(即 C:\Users\你),其余完全一致。

三、动手:五步完成(macOS 为主,Windows/Linux 差异标注)

第 1 步 · 找到(或创建)配置文件

macOS打开终端(Terminal),执行:

mkdir -p ~/.codex
nano ~/.codex/config.toml     # 或 open -e 用文本编辑打开

Windows打开 PowerShell:

mkdir $env:USERPROFILE\.codex -Force
notepad $env:USERPROFILE\.codex\config.toml

Linux与 macOS 完全相同(nano ~/.codex/config.toml)。

文件已存在就直接编辑——改之前先复制一份备份(手动方案的保命符):

cp ~/.codex/config.toml ~/.codex/config.toml.bak

第 2 步 · 写入供应商配置块(可直接抄,改两处)

# 顶层:当前默认使用哪家(指向下面那个块的名字)
model_provider = "myrelay"

[model_providers.myrelay]
name = "我的供应商"                        # 显示名,随便起
base_url = "https://api.myrelay.com/v1"   # ← 改成供应商给你的地址
env_key = "MYRELAY_API_KEY"               # Key 存在哪个环境变量里
wire_api = "responses"                    # 协议:responses(新版)或 chat(传统)

逐行说明:

  • model_provider:顶层开关。想换第二家时,改的就是这一行——记住它,后面讲切换痛点时会再见到。
  • base_url:供应商文档里给的接口地址。/v1 带不带以文档为准;Codex 会在它后面拼接具体接口路径。
  • env_key:只写变量名,不写 Key 本身。这是安全设计——Key 永远不进配置文件、不进 git。
  • wire_api:供应商支持哪种填哪种(文档会说明)。填错的典型症状是 404 或参数报错。

第 3 步 · 把 Key 放进环境变量

macOS(zsh,当前 Mac 默认):

echo 'export MYRELAY_API_KEY="sk-你的key"' >> ~/.zshrc
source ~/.zshrc

Linux(bash):

echo 'export MYRELAY_API_KEY="sk-你的key"' >> ~/.bashrc
source ~/.bashrc

Windows(PowerShell,setx 写入用户变量,永久生效):

setx MYRELAY_API_KEY "sk-你的key"
# 注意:setx 不影响当前窗口 —— 关掉重开一个 PowerShell

第 4 步 · 新开终端,新开会话

这一步 90% 的"改了没生效"都栽在这:codex 只在进程启动时读一次配置和环境变量。正确动作:关掉当前终端窗口 → 开新窗口(加载新环境变量)→ 运行 codex 新会话。

第 5 步 · 验证配成功了

  1. 变量在不在:echo $MYRELAY_API_KEY(Windows:echo $env:MYRELAY_API_KEY)——能打印出 Key 才算数。
  2. 上游通不通(可选): 
    curl https://api.myrelay.com/v1/models \
  -H "Authorization: Bearer $MYRELAY_API_KEY"
    返回模型列表 JSON = 地址与 Key 双双正确。401 = Key 错;404 = 地址路径错(先怀疑 /v1)。个别供应商不提供 models 列表接口,此步 404 但第 3 步正常,也算通过。
  3. 实战:新开的 codex 会话里随便问一句,正常流式回复 = 链路全通。

四、常见报错速查表

症状最可能的原因解法

五、想配第二家、来回切?手动方案的真实成本

再接一家:回到第 2 步,多写一个 [model_providers.second] 块、再导出一个环境变量——这些是一次性的。贵的是每次切换:

切换 = 打开 config.toml
      → 改顶层 model_provider 那一行
      → 保存
      → 关掉当前终端窗口
      → 新开窗口
      → 新开 codex 会话
      → (可能还要重试刚才没发出去的问题)

一天切一次是仪式感,一小时切几次就是折磨——而"这家限流了换那家""这个模型走官方、那个走第三方"恰恰是重度用户的日常。配置文件解决不了这个问题,因为它没有记忆、不认识"切换"这个词。这正是后来各类管理工具诞生的原因——但在那之前,值得先把 Claude Code 和 Gemini CLI 的手动配置也走一遍,你会对"麻烦"有更完整的认识。下一篇见。

常见问题

auth.json 是什么?和我的配置冲突吗?

~/.codex/auth.json 存的是 OpenAI 官方登录(订阅模式)的凭据;自定义供应商走 config.toml + 环境变量,两套机制互不影响。

Key 明文放在 .zshrc / .bashrc 里安全吗?

本机可读性与 config.toml 相当,风险主要在把 dotfiles 同步到公开仓库或截图外发。绝不提交进 git 是底线。

两家供应商能同时"在线"吗?

配置块可以并存,但顶层 model_provider 只有一个当前值;切换必须改文件 + 重开会话。

有没有不用每次改文件的办法?

有——本系列后半部分会讲到管理工具的原理(本地代理接管);急用可先看 Keyway 使用指南。
